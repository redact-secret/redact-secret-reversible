`@redact-secret/vault` 0.1.0-alpha.1 implements the three records accepted on 2026-09-27 for its in-memory, whole-input scope. Their *Resolved choices* sections fix the token grammar, default use count, limits, linearization point, and (for Worker mode) the message protocol, and cite the qualification evidence. The server authority interface ([#15](https://github.com/redact-secret/redact-secret-vault/issues/15)) is decided as a contract, generalizing that same model with principal/tenant/purpose. Worker mode (V4, [#14](https://github.com/redact-secret/redact-secret-vault/issues/14)) is implemented and qualified. `@redact-secret/vault-server` 0.1.0-alpha.1 ([#16](https://github.com/redact-secret/redact-secret-vault/issues/16)) is its first concrete implementation, with an in-memory backend built on `@redact-secret/vault`. A research-grade Python implementation also exists ([#17](https://github.com/redact-secret/redact-secret-vault/issues/17), `packages/vault-py`, distribution `redact-secret-vault` since [#56](https://github.com/redact-secret/redact-secret-vault/issues/56) — see the dated note on the [naming decision](2026-09-27-name-vault-packages-and-language-contract.md), in-memory storage, capture through a documented Node.js service boundary to the core — no native Python core distribution exists; see [docs/research/python-server-integration-2026-09-27.md](../research/python-server-integration-2026-09-27.md)). The persistent-store contract ([#19](https://github.com/redact-secret/redact-secret-vault/issues/19)) is likewise decided, generalizing F4's linearization requirement with atomicity, encryption, key ownership, and deletion semantics for a store beneath S1; no backend implements it yet. Opt-in PII detection in core `0.1.0-beta.10` is decided as a contract ([#45](https://github.com/redact-secret/redact-secret-vault/issues/45)), implemented on every surface, and qualified with PII off and on ([#42](https://github.com/redact-secret/redact-secret-vault/issues/42)), unreleased; the `0.1.0-alpha.2` candidate ([#44](https://github.com/redact-secret/redact-secret-vault/issues/44)) carries it, and publication awaits maintainer approval. A `pii_` finding is never retained without a PII-specific allowlist. The application, not the vault, owns the core's realm-global PII activation. The vault stays compatible with beta.9 by feature detection. Still open: a concrete qualified persistent backend ([#20](https://github.com/redact-secret/redact-secret-vault/issues/20)), cross-language JS/Python conformance documentation ([#18](https://github.com/redact-secret/redact-secret-vault/issues/18)), arbitrary-text restore semantics, streaming, and Rust/Go threat models. The [threat model](../specs/threat-model.md) states each mode's boundary. See [security research](../research/security-foundations-2026-09-27.md) and the [pre-implementation plan](../plans/pre-implementation.md).
