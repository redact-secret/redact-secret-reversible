# Keep typed display placeholders independent from reversible identity

## Decision

Core typed placeholders are presentation of safe finding metadata. They remain available without this repository and do not create retained plaintext. A reversible token must be issued and recognized by an opt-in session mapping. Its visible type, if present, is descriptive and cannot establish lookup authority.

## Rationale

The core already supports default `<SECRET_1>` and typed formatting (for example `<JWT_1>`) through a formatter that sees finding metadata, not matched plaintext. A future `ssn` finding could be displayed as `<SSN_1>` without adding restoration. Conversely, a deterministic label can occur literally in source text, be copied between sessions, or be generated by a model. It cannot distinguish an issued mapping entry from an arbitrary string.

## Consequences

- Core detector types and formatters need no knowledge of restoration or mapping stores.
- This repository consumes finding type as optional display metadata and does not hardcode PII categories such as SSN.
- Restore checks use exact issued identity plus session/tenant binding and authorization, never a regex over `<TYPE_N>`.
- Changes to display format cannot silently change authorization or mapping lookup. Token syntax and escaping need dedicated tests.
- An application may use core typed placeholders without installing this package. Installing this package does not make pre-existing core placeholders restorable.

## Open questions

Choose an issued-token grammar or a separate structured handle, collision behavior when literal tokens appear in input/output, and whether to include a human-readable type label at all.
