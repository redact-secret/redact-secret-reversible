# JavaScript and Python: runtime and version matrix, equivalent outcomes, and differences

**Status:** a record of what was run and what was compared, written for [#18](https://github.com/redact-secret/redact-secret-vault/issues/18) (S4) under epic [#3](https://github.com/redact-secret/redact-secret-vault/issues/3). It supports no new claim. Nothing here promotes a runtime, a backend, or a language: **Python persistence is not supported**, and the [Python qualification record](qualification-python-persistence-0.1.0b3.md) is the only document that may state support for a Python persistence cell. This record carries over and checks the items of the [server epic reconciliation](server-epic-reconciliation.md) that #18 left open: the exact runtime and version matrix, the equivalent-outcome evidence, and the candid differences.

**Recorded 2026-10-02**, on `main` at `cb54581` plus the working tree of the change that adds this file. A "cell" is one combination that was actually run. A cell that is not in a **Run** column was not run, and no sentence anywhere claims it. A skipped test is not a pass.

## 1. What the core pin means

Every distribution pins `@redact-secret/core` to **one exact version, `0.1.0-beta.12`**, and does not claim a range: `@redact-secret/vault` and `@redact-secret/vault-server` as an exact peer dependency (`packages/vault-server/package.json`), the Python bridge as `PINNED_CORE_VERSION` in `core_client.py`. A bridge response that reports another version is `CORE_FAILURE` / `CORE_VERSION_MISMATCH`. [CONVENTIONS.md](../../CONVENTIONS.md#releases) asks for integration tests at both ends of any supported range; with a range of one version, both ends are the same version, and the matrix below is run against it. The history of earlier pins (`0.1.0-beta.9` to `0.1.0-beta.12`, and which published release pinned which) is in [docs/status.md](../status.md); corpus 1.3.0 also passed unchanged on `0.1.0-beta.11` ([conformance/README.md](../../conformance/README.md)). Nothing in this repository claims a core version other than the pin.

## 5. Differences between the JavaScript and Python servers

Each row was carried over from the [reconciliation](server-epic-reconciliation.md) (rows 1 to 8), from section 6 of the [Python record](qualification-python-persistence-0.1.0b3.md) (rows 9 to 13), or from the archived [Python integration record](https://github.com/redact-secret/redact-secret-vault/blob/0db9a33a654704f1afad9388f5fdf0cf403a6b01/docs/research/python-server-integration-2026-09-27.md) section 5 (rows 14 to 18), and **re-checked against the code and tests of this tree** with the method in the last column. "Python persistent" is the unpublished, unsupported profile. Whether a difference is intended or a defect is the maintainer's decision; this table records what is true.

| # | Topic | JavaScript | Python in-memory (published `0.1.0b3`) | Python persistent (tree only) | Re-checked by |
| --- | --- | --- | --- | --- | --- |
| 1 | **Source of `policyRevision`** | Stamped at capture from the server option (`policyRevision`, a string or a function) and echoed in every decision tuple; the caller cannot supply it. ## 6. What this record does not settle

- **A shared server-case corpus.** The reconciliation's item (b) and (c) asked for a server-API corpus runner for `@redact-secret/vault-server` or a rewording of the #16 claim "passes the shared corpus"; this record does neither. The wrapped `Vault` passes the corpus and the Python server passes it; the server API's own order is pinned by parallel tests in each language.
- **Whether each difference is intended.** Rows 1, 2, 3, 5, 10, 11, 17 are design differences that the persistent profile in Python narrowed toward JavaScript; rows 8 and 9 are test or reporting differences. A maintainer decides which stay.
- **Rust and Go.** They remain separately planned; this record says nothing about them.
